# 6. Диагностика компьютера

Занятие 6. Диагностика компьютера и
устранение типичных проблем
Продолжительность: 90 минут · Результат: диагностический отчёт,
основанный на наблюдениях и проверяемых гипотезах.


Цели

Ученик учится отличать симптом от причины, пользоваться
Диспетчером задач, сведениями о накопителе и событиями Windows;
составлять безопасный план диагностики без случайных вмешательств.


Теория

1. Диагностика — это последовательность гипотез
Сообщение «компьютер тормозит» — наблюдение, но не диагноз.
Нужно уточнить: когда проявляется проблема, в каких программах,
после каких действий, есть ли ошибка, повторяется ли, каковы условия
сети и питания. Записываем симптом → возможная причина →
проверка → наблюдение → вывод. Хорошая диагностика часто
заканчивается фразой «данных пока недостаточно» вместо
необоснованной уверенности.

2. Узкие места: CPU, RAM, диск, сеть
Когда CPU перегружен, вычислительные задачи могут выполняться
дольше. Нехватка RAM может вызвать интенсивную подкачку;
перегруженный диск тормозит загрузки/сохранения. Сеть может
ограничивать удалённые приложения, даже если локальный ПК
быстрый. Метрики меняются во времени, поэтому одно мгновенное
значение не гарантирует реальную причину проблемы.

3. Диспетчер задач и Монитор ресурсов
Диспетчер задач показывает процессы и текущие показатели. Монитор
ресурсов ( resmon , если доступен) позволяет детальнее наблюдать CPU,
память, диск и сеть. Высокая загрузка во время обновления или
копирования может быть ожидаемой. Наблюдение полезно, когда
сопоставляется с конкретным воспроизводимым действием
пользователя.

4. Диск и свободное место
Если системный диск почти заполнен, программы и обновления могут
испытывать проблемы. Проверить можно через Параметры → Система
→ Память и свойства диска. Утилиты для очистки могут предлагать
удалить временные или пользовательские файлы; перед удалением

нужно понимать последствия. На учебном занятии ничего не удаляем
за пределами учебной папки.

5. Обновления и драйверы
Устаревшие версии ПО или драйверов могут быть причиной
несовместимости, но обновление — не универсальное лекарство.
Важно знать историю изменений: проблема появилась до обновления
или после? Обновления Windows и драйверы предпочтительно
устанавливать из официальных источников по согласованию. Не
следует использовать неизвестные «driver booster» инструменты.

6. Журналы событий
Просмотр событий Windows хранит разные события: информационные,
предупреждения и ошибки. Наличие записи уровня Error не означает
катастрофу: необходимо сопоставлять время, источник и конкретный
симптом. По коду события можно искать документацию производителя.
Ученик должен научиться описывать событие словами, не удаляя
журналы и не изменяя системные настройки.

7. Перегрев и энергосбережение
Перегрев или ограничение мощности могут снижать
производительность. Для ноутбука существенны подключение питания,
выбранный режим энергопотребления и вентиляция. Встроенные
средства Windows не обязаны показывать все температуры
компонентов. Без специального оборудования/программы не стоит
выдавать предположительную температуру за измерение. Чистка
системы охлаждения — физическое вмешательство, не часть этого
практикума.

8. Безопасный план устранения
Сначала сохраняем работу, фиксируем ошибку и делаем
воспроизводимый тест. Затем проверяем доступность диска, загрузку
CPU/RAM, наличие обновлений, перезапуск только целевого
приложения. Любое изменение выполняем по одному и проверяем
результат; тогда легче понять причину. Для серьёзных проблем —
резервная копия и обращение к специалисту. «Ускорители»,
«чистильщики реестра» и отключение защитных механизмов
исключаем.

Практикум на ПК

Задание A. Состояние системы (10 минут)

 1. Открой Диспетчер задач → Производительность; запиши CPU/
   RAM/Диск в состоянии покоя.
 2. Запусти Блокнот и Проводник, наблюдай изменения.
 3. Открой Параметры → Система → Память и проверь долю занятого
   пространства (без удаления данных).
 4. Заполни шаблон диагностического отчёта.

Задание B. Контролируемая нагрузка (10 минут)

 1. На учебных файлах из урока 3 скопируй несколько небольших
   объектов и посмотри, как меняются показатели диска.
 2. Прекрати копирование, сравни значения до/после; не создавай
   искусственную тяжёлую нагрузку.
 3. Объясни, почему кратковременная загрузка диска при копировании
   ожидаема.

---

Задание C. Просмотр событий (8 минут)

 1. Win + R → eventvwr.msc , открой Журналы Windows → Система
   (если доступно).
 2. Найди три недавних сообщения и запиши только время, уровень и
   источник (без конфиденциальных данных).
 3. Не заявляй, что сообщение связано с проблемой, если такой связи
   не проверено.
 4. Не очищай журналы.

Задание D. Учебный кейс (7 минут)
Ситуация: ноутбук медленно работает при одновременном запуске
браузера с множеством вкладок и видеосвязи. Учебные наблюдения:
RAM занята на 94%; CPU — 28%; свободно 40% SSD. Предложи
минимум 3 безопасных действия и объясни, какие данные ещё нужны
для окончательного вывода.


Самостоятельная работа

Напиши краткий алгоритм из семи действий «что делать, если
компьютер внезапно стал медленным»; укажи, что нельзя делать до
резервного копирования.


Домашняя работа

Сдать diagnostic-report.md по реальной системе или предложенному
кейсу. Обязательно разделить разделы «наблюдения», «гипотезы»,
«проверки», «выводы» и «рекомендации».

Повышенная сложность: сформулируй альтернативное объяснение
симптома, которое не связано с аппаратной производительностью.
