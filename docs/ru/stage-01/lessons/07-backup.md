# 7. Резервное копирование и восстановление

Занятие 7. Архивирование, резервное
копирование и восстановление
Продолжительность: 90 минут · Результат: резервная копия учебных
данных и проверенное восстановление.


Цели

Ученик различает архив, резервную копию, синхронизацию и
восстановление, знает правило 3-2-1 и умеет доказать
работоспособность простого резервного сценария.


Теория

1. Почему данные теряются
Причины: случайное удаление, ошибка программы, поломка
накопителя, вредоносное ПО, физическое повреждение/кража
устройства и ошибка синхронизации. Хранение единственной копии на
одном диске создаёт единую точку отказа. Резервное копирование —
это не обещание «файл где-то есть», а управляемая возможность
восстановить его из независимой копии.

                                 LOCAL COPY
                                external storage
       ORIGINAL                                         RESTORE
      working copy                                     test + verify


                                   OFF-SITE
                                another location

2. Архивирование и резервная копия — не одно и то же
Архивирование объединяет и/или сжимает файлы; резервирование
создаёт отдельную копию для восстановления. ZIP-файл, оставленный
на том же единственном физическом диске, плохо защищает от отказа
этого диска. Иногда архивы используются внутри резервной стратегии.
Резервная копия может содержать несжатые файлы, если так проще
гарантировать восстановление.

3. Правило 3-2-1
Практическое правило: иметь три экземпляра данных (основной +
минимум две копии), использовать минимум два различных типа
носителей/сред, хотя бы одну копию хранить отдельно от основного
устройства/места. Это рекомендация, не магическая гарантия:
дополнительно важны проверка восстановления, защита от удаления и

---

управление доступом. Для важной информации полезна автономная/
неизменяемая копия.

4. Полная, инкрементальная и дифференциальная копии
Полная содержит весь выбранный набор данных. Инкрементальная
сохраняет изменения относительно предшествующей копии в цепочке.
Дифференциальная обычно сохраняет изменения относительно
последней полной копии. Восстановление инкрементальной цепочки
может требовать все её элементы; для дифференциальной — полную и
актуальную дифференциальную. На этом этапе делаем простой полный
учебный бэкап, без сложных систем автоматизации.

5. Версионирование и точки восстановления
Файл можно случайно испортить и затем синхронизировать ошибку на
все устройства. Поэтому полезно сохранять версии и исторические
копии. Точка восстановления системы Windows помогает отменять
некоторые системные изменения, но не является полноценной
резервной копией пользовательских файлов. Для документов нужен
отдельный механизм сохранения копий.

6. Windows File History, облачная синхронизация и другие
инструменты
История файлов Windows может сохранять версии пользовательских
файлов на внешнем/сетевом накопителе, если настроена и доступен
носитель. OneDrive/другое облако может синхронизировать данные и
предоставлять историю версий, но синхронизация сама по себе не
гарантирует защиту от любого вида потери. Нужно учитывать квоты,
доступ к аккаунту, восстановление удалённых элементов и условия
поставщика. Не загружай в чужие облака конфиденциальные данные
без разрешения.

7. Проверка целостности
Проверка наличия ZIP — слабее проверки реального восстановления.
Нужно открыть восстановленный файл и убедиться в содержимом. Для
байтового сравнения можно применить хеш-функцию (например
SHA-256). Одинаковый надёжный хеш с крайне высокой вероятностью
означает одинаковое содержимое. Для начинающего практическое
открытие файла обязательно, вычисление хеша — дополнительный
навык.

8. План восстановления
Полезный план отвечает на вопросы: что копируется, куда, как часто,
кто отвечает, как восстановить, как проверить. Приоритеты
различаются для личных фотографий и временных учебных файлов.
Отдельно нужно проверить, не забыты ли важные настройки/базы

данных; копия одних ярлыков не восстановит установленное
приложение.

Практикум на ПК

Задание A. Подготовить учебные данные (7 минут)

 1. В Документы\it-course\stage01 создай backup-lab\source и backup-
   lab\restored .

 2. Создай source\report.txt с тремя предложениями,
    source\tasks.txt с пятью задачами; можно скопировать
   обезличенные учебные файлы из урока 3.

3. Запиши количество и приблизительный размер объектов. Не
   используй личные фотографии, пароли или банковские
   документы.

Задание B. Создать отдельную копию (10 минут)

 1. При наличии внешнего носителя/отдельного согласованного
   облачного места сделай копию туда. При отсутствии — для
   демонстрации скопируй папку в backup-lab\backup-demo , но честно
   подпиши «учебная копия на том же устройстве: не полноценная
   защита от отказа диска».
 2. Для удобства создай ZIP с содержимым source .
 3. Сохрани его в согласованном месте, не удаляя исходные данные.
 4. Запиши в журнал источник, цель, дату, содержимое и ограничения.

Задание C. Тест восстановления (10 минут)

 1. Из копии/ZIP восстанови файлы в backup-lab\restored .
 2. Открой оба файла, сравни содержимое с исходными. Убедись, что
   изменённые после копирования данные не должны неожиданно
   появляться в старом бэкапе.
 3. Отметь результат каждого файла в журнале: восстановлен / не
   восстановлен / требует проверки.
 4. Не перезаписывай оригиналы и не стирай учебные исходники во
   время теста.

Задание D. Проверить хеш (8 минут, дополнительный навык)

 1. Открой PowerShell в учебной папке (без запуска от
   администратора).

 2. Выполни для выбранного безопасного учебного файла (замени путь
   на действительный):


     get-filehash -algorithm sha256 '.\source\report.txt'
     get-filehash -algorithm sha256 '.\restored\report.txt'

 3. Сравни значения Hash. Если пути не совпадают с фактическим
   местом или команда не выполняется, обсуди с преподавателем и
   ограничься открытием/сравнением файлов вручную.

 4. Измени в восстановленной копии один символ, повтори проверку
   и объясни изменение хеша.
