# 4. Software Installation and Configuration

4. Software Installation and Configuration
Duration: 90 min · Deliverable: documented, verifiable installation or safe
observation


Learning outcomes

Choose trustworthy software sources, check legal use and compatibility,
understand elevation requests and verify an installation without damaging
the device.


Theory and examples

1. Applications and installers
An application consists of executable code, configuration, resources and
sometimes dependent libraries. An installer places and registers required
components, creates shortcuts and may request additional permissions.
Portable apps sometimes run without a system-wide setup; this does not
imply that they are exempt from license terms.

2. Trustworthy sources
Prefer the developer’s website or a trusted app store. Search
advertisements and mirrored download pages can lead to modified or
bundled installers. Verify the publisher, URL spelling and version before
launching a file. Never use pirated activation tools or disable security
protection at an installer’s request.

3. Compatibility and requirements
Check whether software supports Windows 11, the machine’s architecture
(x64/ARM), the available disk space, and any prerequisites. A 32-bit
application may run on many 64-bit systems, but not every architecture
pairing is supported. A successful download says nothing about installation
compatibility.

4. Licenses and activation
A license defines permitted use, redistribution and sometimes number of
devices or users. Installation copies software; activation may validate rights
to use particular features. Freeware, open-source licenses, trials and paid
licenses are distinct. Keep account credentials and activation keys private
and never add them to public reports.

5. Administrator requests and UAC
Windows User Account Control warns when a task seeks elevated
permissions. Administrative access may be required for system-wide
changes, but a prompt is not proof that a file is safe. Check the program

6. Installation choices
Some installers offer scope (current user/all users), directory, optional
modules and telemetry settings. Read each screen and avoid unwanted
add-ons. Do not change default system directories without a reason. A
portable app might instead be placed inside a chosen practice folder.

7. Verification and troubleshooting
An installation is complete only when the required functions work. Launch
the program, inspect its version, create a harmless test file and reopen it if
applicable. Record errors without deleting logs. If a problem occurs,
distinguish installation failure from missing license or incompatible
hardware.

8. Updating and uninstalling
Updates may resolve security vulnerabilities and compatibility problems.
Before uninstalling, identify whether the application stores personal data
that could be deleted. Use Windows Settings → Apps → Installed apps and
follow the normal removal process. Never remove random entries from
system folders or the registry as a cleanup shortcut.

Guided practice on a computer

A. A. Check an application before installing

 1. Choose an approved free application such as a plain-text editor or use
    an application already installed.
 2. Find its official website and note publisher, current version, license and
    system requirements.
 3. Record the source address, checked information and any reason to
    postpone installation.

Completion criteria: The software source and use rights are justified.

B. B. Install or observe safely

 1. If the teacher/device owner permits, install the selected application;
    otherwise observe a demonstration.
 2. Read installation steps, identify optional components and note any UAC
    prompt without accepting unknown elevation.
 3. Record where the application appears in the installed-apps list; do not
    expose personal details.

Completion criteria: No unauthorized system change occurs.

C. C. Verify the result

 1. Launch the application and locate About or version information.
 2. Create a harmless practice document, save it in it-course/stage01 ,
    close and reopen it.
 3. If installation was observation-only, document which verifications were
    seen and which were not.

Completion criteria: A real function was tested or explicitly marked
unverified.
