# 8. Final Practical Workshop

8. Final Practical Workshop
Duration: 90 min · Deliverable: complete, evidence-based workstation
preparation report


Learning outcomes

Integrate hardware, Windows, files, safe software selection, permissions,
diagnosis and backups into one documented practice case.


Theory and examples

1. Start with the user’s goal
Before changing a machine, identify its owner, the intended tasks and
acceptable risks. Record the initial state, including missing information. A
student workstation may need a browser, office tools and backups but not a
gaming GPU. State the scope so that unrequested changes do not slip into
the work.

2. Inspect before configuring
Check Windows edition/build, CPU, RAM, disk capacity and free space
using built-in tools. Measurements reflect a particular moment. Do not infer
that an unfamiliar process or drive value is faulty. Record where each fact
was observed so another person can repeat the check.

3. Organize files predictably
Separate inputs, working copies, outputs, backups and reports. Stable
names and visible extensions reduce accidental overwrites. Never use
private customer data in training assignments. A clear folder tree is a
practical deliverable that another person can navigate.

4. Verify software and its license
A program is acceptable when its distribution source, system compatibility
and allowed use have been checked. The required functionality must be
tested, not assumed from the presence of an icon. If installation is
prohibited on the current machine, document a read-only observation or
teacher demo instead.

5. Access and system safety
Use ordinary user privileges for daily tasks; do not grant additional rights
just to save clicks. Any UAC or administrative operation requires a justified
purpose and permission. Inspect only practice-folder permissions. Leave
security settings, Windows services and device drivers unchanged unless a
qualified owner explicitly authorizes a task.

---

6. Diagnosis rather than guessing
Record symptoms, observations, hypotheses and low-risk checks. A heavy
CPU workload or an Error event does not alone establish a failure. Compare
behavior against the user’s goal. Explicitly mark unknown causes and
actions not performed.

7. Backup with proven recovery
Creating a ZIP is not completion of the backup exercise. Make an approved
independent copy when possible, restore a practice file to another location
and open it. Explain any remaining limitation such as the use of a second
folder on the same disk.

8. Presenting the result
A final report should include initial conditions, activities, measurements,
verified outcome and remaining risks. Show the reader where files are
stored and how to repeat a check. Do not include credentials, product keys
or personal identifiers. Concise, reproducible evidence is more useful than
“everything is done.”

Guided practice on a computer

A. A. Inspect and plan (10 min)

 1. Describe three realistic needs of the intended computer user.
 2. Record Windows edition, CPU, RAM, storage and free space as
    available; do not expose unique identifiers.
 3. List the scope and any unknown or unauthorized operations.

Completion criteria: The initial state and user goals are documented.

B. B. Arrange files and validate software (20 min)

 1. Create it-course/stage01/capstone/
    {input,working,output,backup,reports} .

 2. Create three synthetic text files; copy one to working , edit it and save
    the finished version to output .
 3. Check a legitimate installed application: source/license if known,
    version and one working function. Inspect practice-folder permissions
    without altering them.

Completion criteria: Originals survive; the application works or is honestly
marked unverified.

C. C. Diagnose, back up and present (30 min)

 1. Inspect CPU, RAM and disk activity; write two hypotheses for a slow
    application and one low-risk check for each.
 2. Copy or archive output to an independent approved location if
    possible; restore the file into a new folder and open it.
 3. Complete final-report.md (two or three pages) with activities,
    evidence, limitations and three preventive measures.

Completion criteria: The resulting report is reproducible and shows a
successful restore.


Independent task

Explain in two minutes what was verified, what remained unknown and why
the chosen actions were safe.

---

Homework

Submit the final report, organized practice folder, restored test file and a
brief self-evaluation against the Stage 1 rubric.

Optional challenge: Propose an onboarding checklist for another student
and explain which instructions must vary by Windows edition.
